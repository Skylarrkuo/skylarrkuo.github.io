给佳能 5D2 重做魔灯菜单，从汉化一路改到界面交接

给我的佳能 5D Mark II 折腾魔灯，最初的要求很简单，菜单换成简体中文，拍照时少翻几层。真正用起来，又觉得有些译名看不懂，小字偏细，底部的操作提示也很难和机身上的按键对应起来。

于是，这次修改逐渐变成了一个面向 5D2 的专版。保留魔灯的功能入口和经典菜单，重新做摄影列表、中文字体、按键提示和相机信息页。后面实机又遇到了退出菜单后按键、拨轮无响应，以及佳能参数页叠加信息乱跳的问题，排查就继续深入到了 ROM 的绘图和事件处理。

这篇整理到 R8 为止。界面已经接入固件并完成编译，部分问题也用相机导出的 ROM 找到了明确证据。退出菜单后的整机卡住仍在验证，暂时没有可以宣布彻底解决的实机结果。

先找一个能继续改的汉化底子

这次使用的是 ryulin456/magiclantern-zh，构建源码固定在 dc3d012aff3ddc0e07df3ceafb9b95dbfdf56f12。选择它，主要是因为有 5D2 专用的完整模块包、源码归档和校验记录，便于把后续修改对应回具体文件。

目标机型始终是 EOS 5D Mark II，佳能原厂固件 2.1.2。文中的修改只围绕这个组合进行，没有向其他机型推广。

原始源码检出保留不动，修改通过脚本应用到独立的构建副本。开发时用了 AI 辅助写代码和排查，实机反馈则不断推翻和修正早期判断。下面说的 R1 到 R8，都是这次定制的迭代编号，与上游自己的发布编号无关。

把常用功能放到第一页

我的使用顺序是拍照优先，兼顾录像。新版首页因此采用六行列表，上方分为“常用、拍摄、辅助、视频、全部”五类。

默认常用项放了斑马纹、峰值对焦、直方图、高级包围拍摄、间隔拍摄和双 ISO。需要什么可以再收藏，模块没有加载、条目不可用时也会显示对应状态。

上图是 R4 的浏览器交互预览，运行共用的菜单 C 代码，状态为模拟输入。右侧按钮只用于电脑试用。

有些功能只是开关，有些会开始拍摄、运行脚本，或进入自绘页面。这些项目不能都用一个 SET 直接执行。列表只对符合条件的普通开关做快捷切换，复杂设置和动作型功能仍交给原有页面处理。

“全部”从已经注册的菜单生成，保留模块和脚本的入口。经典菜单也保留下来了，从“全部 → 经典菜单”切过去，再从经典菜单的“设置 → 菜单界面”切回来。隐藏条目仍遵循原来的隐藏设置，未加载的模块仍需先启用。

这样改完，日常操作可以停留在列表里，偶尔要调整细项时再进入原页面。内部菜单名、配置键和脚本查找接口继续沿用原来的标识，中文只负责显示。

有些译名，得看过功能才知道怎么改

汉化最费时间的部分，是对着代码确认一句话究竟指什么。几个看起来通顺的旧译名，放进相机里就容易让人误会。

之前的译法 调整后的译法 修改原因
景深合成 焦点包围拍摄 相机拍摄不同焦点的照片，合成还要交给后期
陷阱对焦 合焦自动拍摄 主体进入预设焦点时触发拍照，名称直接说明动作
跟随对焦 按键跟焦 用按键驱动镜头，旧译名容易让人以为是主体追踪自动对焦
恢复 ISO 副 ISO 指双 ISO 的另一档感光度
裁切标记 构图参考线 显示构图辅助线，不会裁掉照片内容
任意声道 任意通道 这里是 ETTR 的图像色彩通道，与音频无关

R4 对已有的 2052 条词条进行检查，1884 条找到了完整原文和使用位置，修订了其中 244 条。后续补漏又增加了 154 条，当前词库共 2206 条。

词库之外还有直接画在屏幕上的文字，例如录制状态、对焦提示、错误通知。另一轮检查补译了 310 条这类文本，涉及 360 处显示调用。多行帮助也调整了处理顺序，先匹配完整译文，再取当前选项对应的行，避免拆开之后查不到翻译。

有些标识保留英文更合适，例如 ISO、RAW、EV、dB，以及需要和文件对应的 DUAL 前缀。另有 168 条历史哈希词条没有定位到完整原文，继续保留，没有算进已经完成上下文校对的范围。外部 Lua 脚本、离线帮助图片和第三方模块也没有全部覆盖。

菜单底部则加入了按键图形。照片风格键复用原有花瓣图案，回放键复用三角符号，SET、INFO、MENU 画成键帽，旁边保留简短动作文字。5D2 机身上能找到哪个键，界面就尽量画出哪个键。

这件事后来还返工过一次。电脑模拟环境使用的字体别名，与相机里的实际字号不一致，导致键帽中的字超出边界。修正时改成明确的字体规格，并按文字实际宽度计算键帽宽度，补上了之前显示不全的部分。

92 万点的屏幕，中文怎么才能看清

5D2 的屏幕是 3 英寸、VGA、约 92 万点，见佳能规格页。这里的点数按 RGB 子像素计算，640 × 480 × 3 = 921600，有效像素是 640×480。

魔灯内部却使用 720×480 的绘图坐标。检查 5D2 平台源码后可以确认，这是原有的显示安排。页面仍要画满这块区域，再按 4∶3 屏幕比例显示，不能直接把所有绘图宽度改成 640。

字体的问题也在这里。原来主要靠一套 32 像素字库缩成小字，细笔画在缩放后容易断开，相邻笔画也可能粘连。中文的笔画比英文密，这种变化很显眼。

后来采用 Noto Sans CJK SC Medium，在电脑上分别生成 20、23、32 像素的点阵，给提示、分类和值、主要列表文字使用。生成时考虑横向 8∶9 的显示比例，使用确定的二值化阈值，不加误差扩散抖动。

这是开发时的点阵比较，左侧为旧字库，右侧为新方案，按整数倍放大，没有做平滑。

相机读取生成好的点阵，不需要装入整套 OTF 字体或字体栅格化引擎。三个字号各有 986 个字形，字形覆盖与边界都做了检查，资源加载失败时也保留回退路径。

不过，电脑上的 PNG 放大后好看，还不能说明三英寸屏幕上一定舒服。显示器的尺寸、缩放和相机 LCD 的处理都会影响观感，所以预览同时保留了 720×480 原图和 640×480 比例图，最后仍要在相机上看。

相机信息页做出来了，读取和显示却各踩了一个坑

相机信息页分为“总览、镜头、机身”三页。快门／拍摄次数用大字显示，电池使用分段条，镜头名称、焦距、光圈、CF 剩余空间等信息分区排列。它只读取已有属性缓存，不修改拍摄参数。

上图为 R4 的示例数据，用于说明布局，不是这台相机的真实计数或读取结果。

仪表页没有把快门次数换算成“剩余寿命”。镜头不报告某个字段，就显示“未报告”，还没有收到有效计数时显示 --，有效的零值才显示 0。

实机测试时，页面出现了数值读不出来的情况。检查转储后，先找到了属性解析的假设错误。例如镜头报文实际是 14 字节，旧判断却要求至少 15 字节，导致已有信息也被挡掉了。对焦模式报文则需要兼容这台 5D2 返回的 2 字节格式。

快门计数也不能把两个字段绑在一起判断。转储中的第二个计数小于第一个，早期逻辑因此把整组数据都判成无效。后来把第一个计数独立处理，附加计数不满足条件时，将总动作和 LV 附加动作留空，不再强行相减。

另一个问题更隐蔽。页面上出现的 u、u%，有一部分来自格式化输出。实际执行佳能 2.1.2 ROM 里的 vsnprintf 后发现，在测试的这些路径中，%u 消耗了参数，却输出了字母 u。同一段代码放到电脑的 C 库里运行，数字当然正常。

R7 针对这个差异作了修改。范围明确的电量、焦距等使用经过验证的格式，完整的无符号快门计数单独转换成十进制字符串。同时按 Canon 函数的长度约定，为字符串结尾预留空间，并处理中文截断，避免留下半个 UTF-8 字符。

这也改变了后面的验证方式。浏览器预览继续用来检查布局，涉及相机函数的行为则尽量执行实际 ARM 固件和原始 ROM，不再用电脑上能显示作为依据。

退出菜单以后，谁还在往屏幕上画

最开始，卡住是在开启双 ISO、使用光学取景器拍摄后发现的，主 ISO 和副 ISO 为 200／400。屏幕还亮着，但按键和拨轮没有反应。之后又观察到，从魔灯返回佳能参数页时，附加信息会乱跳。

这个现象让排查重点转向了菜单交接和叠加显示。到 R8，已经在受控条件下确认了几件事。

第一，菜单虽然关闭，正在绘制的旧菜单帧仍可能提交到可见显存。R8 把最后一次提交与前缓冲交接放到同一把绘图锁下，并在锁内复核菜单状态，已经关闭就丢弃这一帧。

第二，参数状态刷新事件 0x3B 会经过按键处理链。旧摄影界面的分支会消耗它，R8 改为让它继续传给佳能处理。

第三，界面切换期间如果暂时没有当前控制器，旧重绘代码会继续访问空指针附近的地址。新代码先检查控制器、对话框和类型，条件不足时退出这次绘制并释放锁。这是在构造的切换条件下验证到的问题，还没有证据说明实机卡住当时就处于这个状态。

原生参数页上还存在另一条绘制路径。魔灯的 FlexInfo 会画时钟、电量、容量、剩余张数等信息，其中也包含清理对应屏幕区域的操作。R8 给它增加了独立开关“全部 → 叠加显示 → 参数页叠加”，默认关闭。手动打开后，绘制前还会复核当前页面。实时取景辅助、相机信息页和经典菜单继续保留。

按键处理也有值得注意的地方。佳能的事件分发会检查控制器标记，标记不匹配时，普通按键和拨轮可能进入队列清理路径。调用返回模式 0 的函数，只表示提交了切换请求，固定等一小段时间也不能证明原生页面已经接管输入。

目前的测试执行了真实 ML ARM 代码和 Canon ROM，使用导出的 RAM 数据，以及受控的事件、计时器和显存输入。它能检查某个分支是否走错、事件是否被消耗、旧帧是否继续提交。完整相机启动、真实任务时序和 LCD 硬件还没有复现，因此这些发现与实机卡住之间的关系仍要继续验证。

R8 同时补充了退出日志，区分事件进入佳能、被魔灯消耗和被佳能队列清理等情况。接下来的实机观察也会把机顶液晶与背屏放在一起看，确认到底是参数还能改变但画面异常，还是输入本身没有得到处理。

启动页、安装器和最终装卡文件

首次打开魔灯时的信息页重新整理过，名字仍用“魔灯”，副标题是“5D2 专版 · 精翻与易用设计”。页面只保留型号、版本和必要的进入操作，去掉界面的署名、邮箱和测试版提示。源码版权、许可证和字体授权保留。

这页每次开机只出现一次，SET 进入菜单，半按快门退出。进入用的那次按键不会顺带修改菜单参数，也不会把用户已经选择的经典菜单强制切回列表。页面文案简化之后，实际验证到哪一步仍按构建记录说明。

期间也怀疑过安装用的 ML-SETUP.FIR 是否不匹配。核对后，使用的 FIR 与对应 5D2／2.1.2 原版安装器逐字节一致，没有证据指向它导致这次异常。正常启动后运行的是 autoexec.bin 和模块，后续 FULL 包已经把经过型号、版本、长度和校验验证的 FIR 一起打包。安装器没有重编译，界面仍为原版。

这里还踩过一次打包问题。双 ISO 的修正在独立构建中已经存在，但 R5、R6 完整包沿用了旧模块目录，修正没有真正进入那些 ZIP。R7 修正构建顺序，逐个核对模块产物与包内文件，R8 继续校验了全部 19 个模块。

所以更新时需要把 autoexec.bin 和完整的 ML 目录一起替换，字体、语言资源、符号表和模块保持配套，并保留个人配置备份。已经能正常启动魔灯的卡，日常更新无需重复运行 FIR。切回经典菜单只改变操作界面，要回退代码则应恢复完整备份。

当前包保留了原有 19 个模块和功能入口，不过有一个具体例外需要说明。排查双 ISO 时，5D2 的双 ISO 回放增强已暂时禁用，RAW 双 ISO 拍摄路径保留。这项取舍也还需要结合实机结果继续评估。

目前停在哪一步

构建在 WSL Ubuntu 24.04 下进行，使用 xPack ARM GCC 14.2.1-1.1，目标仍是实际相机版本。每次输出除了固件包，还保留字体与词库检查、模块依赖、文件哈希和相应测试记录。

目前的 R8 核心为 509632 字节，完整包包含 19 个模块、中文资源和匹配的 FIR。代码里确认的格式化、属性长度、菜单帧提交及事件处理问题已经作了对应修改。部分早期页面经过实机使用，但整套功能、拍摄和长时间运行并没有完成全面验证。

这次最初想解决的是“菜单不好用”，最后花时间最多的却是一个数字怎么显示、一个事件该交给谁、菜单关掉之后还有谁在画屏幕。新列表和中文字体已经有了比较明确的样子，下一步仍是把退出菜单、返回佳能参数页、继续调整参数这一段在实机上查清楚。

本文提到的定制改动尚未提交上游，开头的 GitHub 链接用于查阅汉化基础项目。R8 的验证结论也只对应本文记录的这套构建。
